**背景**:WoW 钓鱼是固定流程,可全自动化。死循环串联「预备 → 前准备 → 抛竿 → 等待 → 位移检测 → 拾取 → 后处理」六个步骤,F11 启动 / F12 停止。位移检测复用 M4 已调到位的参数与 tracker。

**Scope**:仅 Tab 内闭环,不入 DB,不引新依赖。

| 14 | SPEC §2.14 ⏳ → ✅ / §6.1 fishing 0% → 95% / §9.3 v1.5 changelog | ✅ | 收口 |

**关键设计落地**:

- 工作线程跑 `FishingLoop._run`;UI 回调全部走 `pyqtSignal` 切回主线程(架构不变量 2)
- `ScreenRecognition` 复用同一实例,模型只在第一次 DETECTING 时加载,后续轮次仅 start/stop 不重 load
- `DisplacementTracker` 每轮新建(避免上轮残留轨迹干扰)
- 触发阶段在 `_on_raw_detections` 回调里挑 `confidence` 最高的目标(D4),写入 `_triggered_target`(加锁,只记首次)
- 位移参数 `DISPLACEMENT_RATIO=0.09 / MIN_DISPLACEMENT_PX=5 / WINDOW_SECONDS=0.5 / TRIGGER_COOLDOWN_S=1.0` 写死在 `fishing/fishing_loop.py`(D6)
- 超时仍走 POST_PROCESS(D3),让通用宏即使没钓到鱼也运行
- 日志精简(D5):只在启动 / 停止 / 异常 / 超时 / 按键失败时 logger,正常轮次只更新 UI

**完结条件**:

- [ ] 按 F11 启动后能跑完一轮完整钓鱼(抛竿 → 等浮漂 → 检测下沉 → 右键拾取)
- [ ] 按 F12 停止 ≤ 50ms 响应,无残留线程,UI 解锁
- [ ] 连续 10 轮无意外中断,统计「成功 / 超时 / 连续失败」准确
- [ ] 钓鱼前准备 / 钓鱼后处理为空时该步骤被跳过,不报错
- [ ] WoW 全屏运行时 F11/F12 仍能拦截
