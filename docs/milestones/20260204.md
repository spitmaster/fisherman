## M2 — recognition 多目标识别策略与健壮性 🚧

**启动**:2026-05-19
**对应 roadmap**:[P0-1](../roadmap.md#p0-1-recognition-多目标识别策略与健壮性)
**主责 agent**:[screen-recognition-engineer](../agents/screen-recognition-engineer.md)
**协同 agent**:[fisherman-orchestrator](../agents/fisherman-orchestrator.md)(任务拆解 + 联调)

**目标**:把 recognition 模块从「单目标 first-hit」升级到「多策略可配置 + 错误可恢复 + FPS 可调优」,使识别在多怪/多按钮/多角色场景下稳定可用。

**交付**(初版骨架,待 orchestrator/recognition-engineer 细化):

| # | 交付物 | 状态 | 备注 |
|---|--------|------|------|
| 1 | 多目标策略接入(Strategy 模式:Top-N / 轮询 / 几何过滤) | ⏳ | 接口设计 + 至少 2 个策略落地 |
| 2 | 错误处理与重试机制(截图失败 / 推理异常 / 点击越界) | ⏳ | 区分可恢复/不可恢复,日志可追溯 |
| 3 | FPS / 延迟性能基线 + 调优 | ⏳ | 先建立基线数据,再针对性优化 |
| 4 | recognition_tab 配置 UI 暴露策略参数 | ⏳ | 与 pyqt5-ui-developer 协同 |
| 5 | SPEC.md §4 recognition 章节同步更新 | ⏳ | 业务规则改动先改 SPEC(架构不变量 1) |

**完结条件**(初版,可由 orchestrator 调整):

- [ ] 至少 2 种多目标策略实现且单元/冒烟可切换
- [ ] 异常路径全部走 logging 而非裸 `print`(顺带消化 TD-3 部分)
- [ ] 建立 FPS 基线数据(写入 SPEC §4 或专门 perf 笔记)
- [ ] 用户在真实场景试用并接受
- [ ] 不破坏架构不变量 3(重任务串行)+ 不变量 6(CPU 推理)

**首发拆解**:由 fisherman-orchestrator 接手做正式 M2 task breakdown,产出后填入 [../todo/20260204.md](../todo/20260204.md)。
